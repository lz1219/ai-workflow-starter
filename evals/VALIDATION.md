隔离 Git 副本安装 project-onboard 与 change-design，源版本和文件摘要自动登记。已有 AGENTS.md 内容保留，已有需求看板检查通过。全新项目安装后，脚本启动检查和离线 doctor 均通过。自动测试还覆盖预览不写文件、冲突停止、重复安装、Claude Code 入口、失败恢复，以及 doctor 区分定制、缺文件和未完成恢复。

## 独立评分器

| 场景 | 原始缺陷 | 手工构造的正确实现 | 验证范围 |
|---|---|---|---|
| Python CLI | 验收失败 | 验收通过 | 预演副作用、返回数量、普通导入 |
| 中断续做 CLI | 验收失败 | 验收通过 | 同时保留先前的去重行为；删除该行为后再次失败 |
| Maven/Spring | 验收失败 | 验收通过 | 5 个独立 HTTP 验收测试及实际测试报告 |
| Gradle＋Node | 验收失败 | 验收通过 | HTTP 验收、打包，并启动真实后端供 Node 调用 |

Java 验证使用 JDK 17、Spring Boot 3.5.15、Maven 3.9.9、Gradle 8.14.3 和 Node 22。正例是评分器校准样例，不是 AI 完成任务的成绩。所有场景使用合成代码和数据。

## 新会话试验的限制

尝试了 Python CLI 的基线和候选工作流新会话。基线遇到连接与超时问题；候选会话启动后，宿主策略拒绝 PowerShell/cmd 的执行，未能读取和修改源码。两次试验均无法用于比较工作流效果，没有尝试绕过宿主策略。

据此增加了明确执行策略拒绝的状态记录，避免把宿主受阻当成工作流质量结论。评分器同时将被测程序删除目标文件、输出非法结果等行为归为任务失败。模型说“完成”但代码未修复的假运行器也会被外部验收判失败。

后续需要在允许试验工作区读写与原生命令执行的环境，固定模型、工具版本、全局 Skills 和依赖环境，按每个场景每种配置至少三次运行，才能形成有参考意义的完成率、耗时与成本比较。
