# 按变更选择技术章节

在 `design.md` 的「现状与技术方案」下按需添加小节。模块、协议和测试入口沿用项目实际约定。验收通过真实调用入口观察结果。

| 改动涉及 | 设计写什么 | 验证示例 |
|---|---|---|
| Web 或桌面界面 | 操作、界面状态、空结果、失败恢复和相关平台差异 | 浏览器或桌面操作后检查界面与持久化结果 |
| HTTP 契约 | 方法、路径、输入校验、响应和错误。按需说明权限、分页、幂等与调用方兼容，链接 OpenAPI | 从 HTTP 入口验证成功和失败场景。前后端分离时检查共享契约及联调 |
| CLI 或脚本 | 命令、参数、输入、标准输出、错误输出、退出码和副作用 | 从真实命令运行，用临时目录核对结果文件和目标状态 |
| SDK 或公共库 | 公开入口、返回值、异常、调用者约束和兼容范围 | 从消费方调用公开接口，按需用最小消费项目验证 |
| 消息或后台任务 | 触发、载荷、状态转换、重试、重复投递和失败去向 | 在隔离环境触发任务或投递消息，核对状态与副作用 |
| 数据处理或 ETL | 输入输出格式、映射、坏数据、增量、重跑及对账 | 用固定样例验证数量、拒收记录和重跑结果 |
| 存储或迁移 | 字段类型、可空性与默认值、关联、约束、索引及查询用途。写清兼容、回填、恢复和项目实际迁移工具及版本 | 验证空库与存量升级、失败恢复和数据校验 |

多方调用顺序或失败分支影响理解时，用 Mermaid 时序图标出真实参与者。关系及基数影响实现时，用 ER 图与表定义对齐。跨模块或跨仓库的需求共用验收编号，各实现记录实际验证，按需补端到端验收证据。
