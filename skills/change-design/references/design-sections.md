# 按变更选择技术章节与图示

设计或评审时读取，按影响选择下面适用的内容，不把整张表复制成每个需求的必填清单。`design.md` 是设计主入口：保留关键决定、必要的图和验收；较长契约、模型或迁移细节可以拆成附件并链接。已有 OpenAPI、Schema、原型或长期规格直接引用，避免维护两套定义。

## 先确定设计深度

| 变化 | 应达到的深度 |
|---|---|
| 局部行为清楚、没有关键取舍 | 用前后行为、改动位置和验证说明即可；简单需求不为凑图补充架构、状态或数据模型。 |
| 有协作顺序、状态规则、数据关系或多个模块 | 展开影响实现的流程、边界和契约，用下方条件选择图；把关键失败分支关联到验收。 |
| 兼容迁移、权限或数据边界、难回退发布 | 在相关设计上补充旧新版本共存、风险、发布与恢复安排，并按项目规则评审。 |

当前事实附代码、测试或契约依据，目标规则附需求或决策来源，待确认的方案明确标注。量化指标、重试次数、权限及保留期限没有依据时给出待讨论建议，不当作已确认要求。

## 未知、实验与决策

先处理会改变当前方案的未知。行为不明就探查或复现；性能原因不明先测量；关键技术可行性不明先做最小实验。已有事实足够时直接使用，不要求所有设计先做原型。

实验说明要验证的假设、最小范围、观察方式和停止条件。使用已有授权内的隔离环境与数据，明确哪些是实验产物、哪些准备进入正式实现。记录实际结果及局限，结果不支持假设时调整建议，不把局部样例推断为生产结论。用户只要求方案时，不把实验扩大为业务实现。

重要决定记录采用依据、适用条件或假设、代价和重新评估条件。例：「当前样例下同步处理满足已约定目标；真实负载持续超出该目标或依赖延迟明显改变时重评」。目标尚未约定时注明待确认，不填虚构数值。重新评估可以维持原决定，也可以提出替代；实施仍依据用户授权和项目规则。

如果复用现有能力、调整配置或缩减范围更合适，说明依据与取舍；停止或改变用户目标须由用户决定，不以技术偏好替代产品决策。

两个备选方案在常规场景下看起来相同时，可以找一个会让调用方观察到不同结果的最小样例。沿已有入口比较同一输入的真实产物、状态或副作用，记录相同的结果、差异和适用范围。例如缺月留空与补零可能得到相同合计，却改变计数与平均值。把剩下需要人决定的业务问题说清，给出有依据的建议。决定确认后，可将这个差异样例纳入验收或回归。

## 按调用入口和数据变化展开

在「现状与技术方案」下保留适用小节。模块、协议和测试入口沿用项目实际约定，验收从真实调用入口观察结果。

| 改动涉及 | 设计写什么 | 验证示例 |
|---|---|---|
| Web 或桌面界面 | 操作、界面状态、空结果、失败恢复和相关平台差异 | 浏览器或桌面操作后检查界面与持久化结果 |
| HTTP 契约 | 方法、路径、输入校验、响应和错误。按需说明权限、分页、幂等与调用方兼容，链接 OpenAPI 并说明本次差异 | 从 HTTP 入口验证成功和失败场景。前后端分离时检查共享契约及联调 |
| CLI 或脚本 | 命令、参数、输入、标准输出、错误输出、退出码和副作用 | 从真实命令运行，用临时目录核对结果文件和目标状态 |
| SDK 或公共库 | 公开入口、返回值、异常、调用者约束和兼容范围 | 从消费方调用公开接口，按需用最小消费项目验证 |
| 消息或后台任务 | 触发、载荷、状态转换、重试、重复投递和失败去向 | 在隔离环境触发任务或投递消息，核对状态与副作用 |
| 数据处理或 ETL | 输入输出格式、映射、坏数据、增量、重跑及对账 | 用固定样例验证数量、拒收记录和重跑结果 |
| 存储或迁移 | 实体归属、关系基数、字段类型、可空性与默认值、唯一约束、索引及查询用途。写清兼容、回填、恢复和项目实际迁移工具及版本 | 验证空库与存量升级、失败恢复和数据校验 |

## 图何时画、画到什么程度

图放在对应设计小节，说明代表当前行为还是本次目标，使用与正文及契约一致的名称。关系、时序和状态优先使用项目支持的 Mermaid；已有建模或原型工具时沿用。图复杂到难以阅读时按场景拆开，并保持参与者和状态命名一致。

| 表达方式 | 使用条件 | 必须说清的内容 | 与正文的分工 |
|---|---|---|---|
| 时序图 | 多方调用的先后、异步行为、事务边界或部分失败影响正确性 | 本次相关参与者、关键请求和返回、同步异步、关键失败分支；按风险体现超时、重试、补偿或重复请求 | 放在「关键流程与异常处理」。事务范围明确标注，接口字段及错误定义引用契约，不把整份接口文档塞进图。 |
| ER 图 | 新增或改变实体关系，基数、归属或关联约束影响实现 | 实体、主键、关联、基数及可选性，说明物理外键还是逻辑关联 | 放在「数据模型与迁移」。字段定义、默认值、唯一约束、索引和数据迁移仍需表格或 Schema；单表加字段可只写前后对比。 |
| 状态图或转换表 | 对象生命周期决定操作是否合法 | 起始与终止条件、触发者、转换条件、非法转换、重复操作与并发冲突 | 放在「状态与业务规则」。转换条件或权限复杂时用表格补充，区分业务状态与界面显示状态。 |
| 模块关系图 | 跨模块、跨仓库、外部集成，或职责和依赖方向改变 | 本次相关边界、责任、调用或数据依赖；必要时标明部署边界 | 放在「现状、改动边界与取舍」。只画影响范围，调用先后由时序图说明。 |
| 流程图或决策表 | 多条件分支、规则优先级或组合影响结果 | 条件、结果、兜底、互斥或优先关系 | 分支少用文字即可；组合规则优先用决策表，减少交叉连线。 |
| 界面草图或原型 | 布局、操作顺序或反馈状态影响用户理解 | 操作入口、加载、空态、错误与恢复、相关平台差异 | 放在「对外契约与交互」。明确用户行为和反馈，不把实现层细节放进产品界面。 |

例如，设计「事件关闭后通知」时，若关闭与通知存在异步失败，时序图需明确关闭结果是否依赖通知、失败由谁处理；生命周期规则复杂时补状态图；新增事件与通知记录关系时补 ER 图。这些业务决定需来自需求或评审，不能从例子推定必须采用异步通知、某种状态模型或某种数据库。

## 横向约束与发布

仅展开本次影响的内容：

- **权限与数据边界**：谁能执行、能访问哪些资源，在哪个入口校验，拒绝时的结果及敏感数据处理。
- **一致性与恢复**：事务边界、并发冲突、重复处理、部分成功和故障恢复。说明保留哪些不变量及如何验证。
- **性能、容量与可靠性**：目标、来源、负载或数据规模、测量环境和验证方法。离线任务、库或设备项目按实际资源与平台约束定义，未知目标列为待确认。
- **方案取舍**：存在实质选择时比较候选方案、采用依据、代价和重新评估条件；沿用现有约定可直接引用，不强凑备选方案。
- **发布与恢复**：对部署、分发、配置或存量数据有影响时，在「实施、验证与发布」说明顺序、兼容窗口、观测信号、停止条件及恢复步骤。代码回滚不等于数据恢复，不可逆步骤说明限制与处理方式。

## 设计一致性评审

围绕本次关键场景逐条核对：

1. 图里的操作、参与者、状态与正文及契约一致；新建组件与拟新增接口明确标记，现有组件有依据。
2. 状态转换条件与权限、数据约束一致；时序中的事务、重复和失败行为有可实施的处理方式。
3. 关键成功、失败、边界和迁移场景对应验收项，实施任务覆盖必要能力，跨模块或跨仓库另有联调安排。
4. 当前行为、目标方案和已交付事实分开，重要未决项能定位影响及阻塞的增量。

若使用图，检查项目渲染环境中的语法和可读性；无可用渲染器时说明未验证渲染。能渲染不代表业务正确。看板脚本只检查编号、关系和验收安排，不能代替上述语义评审，也不能证明实际验收通过。
