# 基础开发规范

按本次改动的影响范围应用这些规则。确定项目规范时，用真实代码、工具配置和已确认的契约替换抽象建议。

| 主题 | 基础约定 | 验证方式 |
|---|---|---|
| 范围与兼容 | 保持现有调用方依赖的行为。新增或变更公共接口、事件、数据格式时，识别调用方与版本影响。 | 契约测试、调用方验证或设计评审。 |
| 输入与权限 | 在可信服务端边界校验输入、资源归属和访问权限。明确空值、重复请求和非法状态的处理。 | 正常、非法、未授权和越权场景。 |
| 错误与日志 | 沿用项目错误语义，保留可定位的失败信息，保护凭据和敏感数据。 | 失败路径测试，必要时检查日志输出。 |
| 数据与副作用 | 明确事务、并发、重试、幂等与部分失败语义。金额和时间按业务约定处理精度、单位和时区。 | 边界、重复执行、回滚或迁移校验。 |
| 可维护性 | 沿用项目命名、模块边界和现有约定。确实需要新增依赖或模式时说明原因和影响。 | 项目已有的格式、静态检查、架构检查和代码评审。 |
| 测试与交付 | 缺陷重跑原始复现，新增或改变行为覆盖关键场景。记录真实运行的命令、结果和剩余验证。 | 本地运行相关检查，CI 运行项目要求的检查。 |

工具可以验证格式、构建、测试或明确的契约。评审者判断业务语义、设计取舍和回滚是否合适。
