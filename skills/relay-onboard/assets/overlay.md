# 团队工作流覆盖层

已安装的 Skill 文件保持上游原样，团队约定写在本覆盖层。更新工作流时只替换
上游文件，本文件由团队维护，不进入 `.ai-workflow.json` 的安装清单。

- 适用项目：
- 维护者：
- 对应上游版本或提交：
- 最后复核：

`target` 填已安装的技能目录名；`covers` 列出本覆盖层替换或补充的上游位置，
格式为 `<相对路径>#<标题>`。登记后 `--doctor` 会核对目标技能和这些标题是否仍
存在；上游改名或删除被覆盖的小节时会报错，需要人工迁移而不是静默失效。

## 覆盖方式

说明本文件是替换、补充还是限定上游的哪一节。例如：

- 替换 `relay-change/references/implementation.md` 的「验收证据」小节。
- 补充 Java 项目的日志与脱敏约定。
- 限定“高风险设计”在本团队的适用范围。

## 规则

写清做法、作用范围和依据。团队硬约束用“必须”，偏好用“通常”。涉及取舍时
记录确认来源和重新评估的条件。

## 与上游冲突时

写明哪一层优先，以及冲突时找谁确认。默认顺序：项目根入口 → 上游 Skill →
本覆盖层；覆盖层与上游语义冲突时停止实施，先核对上游变更。

## 复核条件

上游修改了被覆盖的小节、项目更换技术栈、或团队约定变更时重新核对。
