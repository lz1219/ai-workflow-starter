# 一张季度月报的两轮设计

维护者希望补齐财务月报里的月份，后来又提出领导要看出哪些月没报。两次业务选择均由维护者在演练中确认。下面按实际决定整理，使用合成金额。可以并排打开[第一轮财务版](finance.xlsx)和[第二轮领导版](leadership.xlsx)，看同一个二月在两次交付里怎样呈现。

## 第一轮：把缺的月份补齐

**提出目标**　“月报导出时，把缺失月份补齐。”

**核对现状**　导出函数原先只遍历有记录的月份。财务模板直接对 B2:B4 求和、求平均。把月份名称补出来可以解决行缺失的问题，金额格如何填写还会影响财务读到的数字。项目已经有金额写入函数和格式约定，导出时继续沿用。[开发指引](AGENTS.md)

**用同一组数据比较方案**　一月上报 120，二月没报，三月确实上报了 0。两种写法的合计都是 120。如果二月留空，平均是 60；如果二月填数值 0，平均是 40。初稿建议留空，理由是缺报与实报零的来源不同。需要确认的是财务按几个月算平均。

**确认财务口径**　“缺月填数值 0，也参与平均。”

**交付财务版**　把三个日历月作为分母写进原设计，将样例的期望值定为 40。财务版保留既有的金额写入函数、两位小数和 Excel 公式。打开第一轮工作簿，B3 和 B4 都是数值零，D3 的季度平均是 40。[原设计与验收样例](design.md)

## 第二轮：领导要看出哪些月没报

回看原决定可以发现，财务版的两个零已经无法表达来源。若从金额为零推断缺报，就会把三月误判为未报。这里有两个独立的变化可以讨论：给领导增加填报状态，或者调整领导看到的平均口径。本轮建议先区分展示，继续沿用财务的季度平均。

**确认适用范围**　“领导想看出哪些月没报，季度平均沿用财务口径。”

**更新原设计**　保留原先两条财务验收，追加领导版和兼容性验收。实现时在读取原始月份记录的位置判断填报状态，领导版增加 C 列。财务调用仍按原来的两个参数导出。[实际实现](export.py)

| 月份 | 源记录 | 财务版金额 | 领导版金额 | 领导版状态 |
| --- | --- | ---: | ---: | --- |
| 一月 | 上报 120 | 120.00 | 120.00 | 已上报 |
| 二月 | 缺少记录 | 0.00 | 0.00 | 未上报 |
| 三月 | 上报 0 | 0.00 | 0.00 | 已上报 |

**核对工作簿**　先比较领导版的二月与三月：金额相同，状态不同。再比较两个工作簿的 D3：都应为 40。下一位开发者如果想改成“只按已报月份平均”，可以从原设计找到受影响的决定，并拿同一个样例重新和维护者讨论。[两轮交付记录](tasks.md)

## 本地复跑

本示例使用 Python 3 和 openpyxl，实际交付用 openpyxl 3.1.5 生成。需要复跑时，在本目录的 Python 环境中执行：

```sh
python -m pip install openpyxl==3.1.5
python -B -m unittest -v test_export
python -B -c "from export import export_quarter; export_quarter({1: 120, 3: 0}, 'my-leadership.xlsx', show_reporting_status=True)"
```

自动化用例重新打开文件检查金额、状态、格式、公式及旧调用。用 Excel 或支持公式的表格软件打开生成文件，可以直接查看 D2 的合计和 D3 的平均值。
